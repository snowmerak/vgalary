# 백엔드 구현·검증 기록

상태: 1차 백엔드 검증 완료. 웹 UI는 미구현. 갱신일: 2026-10-31 (Asia/Seoul).

## 구현한 동작

- Go HTTP API, SQLite 설정·소스·카탈로그·작업·검색 프로필·삭제 의도 저장.
- 앱 설정의 URL·Model과 선택적 환경 변수 참조. API Key 원문을 저장하지 않는 환경 변수 이름 방식.
- 인덱싱 디렉토리 여러 개 등록·제거, 진행 작업 취소, 제거한 소스의 검색 제외와 원본 보존.
- 깊이 제한 없는 폴더·ZIP·RAR 탐색, Windows Junction/심볼릭 링크 조상 순환 감지, 중첩 압축의 조상 해시 검사. 다른 경로의 동일 내용은 위치를 보존하고 벡터만 재사용.
- llama.cpp 멀티모달 임베딩, Qdrant REST 컬렉션·포인트 저장과 검색, 재시도의 인증 헤더 유지.
- H.264/H.265 NAL 기반 IDR 선택과 PTS 저장. AV1 등은 설정으로 허용한 키프레임 대체를 별도로 기록.
- 자연어 검색, 영상 단위 결과 묶기와 일치 프레임 타임스탬프 반환, 미디어 ID 기반 썸네일·Range 콘텐츠·중첩 압축 다운로드·서버 측 내보내기 API.
- 내용이 같은 자료의 임베딩 재사용, 저장 중단 후 작업 재개, 불완전 스캔의 기존 자료 보존, 삭제 실패의 영속 재시도.
- 모델·전처리 프로필 변경 시 등록한 모든 소스의 준비를 확인한 후 검색 프로필 전환.

## 실제 서비스와 사용자 미디어 검증

환경은 Windows ARM64, Go 1.27.3, FFmpeg 9.0.2, llama.cpp의 `embed` 별칭(`ggml-org/embeddinggemma-2-GGUF:Q8_0`), Qdrant 1.20.0이었다. Docker 엔진의 응답이 없어 허용된 대안인 WSLC로 Qdrant를 실행했다.

원본 사진 네 장과 219.481초 AV1 WebM을 복사해 테스트 데이터를 만들었다. 원본은 변경하지 않았다. 일반 파일과 24단계 폴더, ZIP 9겹 → RAR → ZIP 구조의 11단계 압축 항목 체인을 포함한다. 생성한 RAR는 독립 도구 `7z t`에서도 통과했다. 로컬 미디어·실행 상태·개별 검증 JSON은 Git에서 제외한다.

아래 표는 화면 변화 필터를 추가하기 전, 전체 키프레임을 사용한 최초 실행 기록이다. 현재 기본 정책을 적용한 결과는 다음 절에 구분한다.

## 화면 변화 기반 프레임 선택 검증

2026-10-31에 영상의 임베딩 대상을 마지막으로 채택한 프레임과 화면이 충분히 달라진 IDR·키프레임으로 변경했다. 첫 프레임은 유지한다. 기본 설정은 `video_frame_change_threshold=0.12`이며, 64×64 RGB 이미지의 정규화 평균 절대 차이를 모델 호출 전에 비교한다. `0`은 필터를 끈 기존 정책이다.

- 제공한 AV1 영상의 후보 79개 중 57개를 선택했다. 영상당 저장·사용 벡터가 22개, 약 27.8% 줄었다.
- 일반·RAR·11단계 압축 체인 내부의 같은 영상 모두 57개씩 저장했다. 이미지 7개 위치와 합쳐 새 활성 프로필은 총 178포인트다.
- 실제 llama.cpp·Qdrant 통합 테스트를 다시 실행해 통과했다. 새 프로필의 이미지 임베딩 호출은 61회(선택한 영상 프레임 57개와 원본 사진 4개)였고, 변경 없는 재스캔에서는 0회였다.
- 선택한 원본 프레임의 PTS·타임스탬프를 보존했고, 두 번째 선택 프레임부터 `change_score`가 임계값 이상인지 실제 카탈로그에서 확인했다. 한국어 사진 검색과 영상 검색·중첩 다운로드·재시작 검증도 다시 통과했다.
- 정적인 H.264 영상의 IDR 3개가 첫 프레임 1개로 줄어드는 FFmpeg 테스트를 추가했다. RGB 색상 변화, 동일 프레임 제거, 점진적 변화 누적, 비활성화, 취소, 설정 이행과 프로필 무효화도 검사했다.
- 정책 변경 시 기본 미디어 목록은 새 활성 프로필만 반환한다. 과거 프로필·컬렉션은 이력으로 보존하므로 위 수치는 새 활성 색인의 포인트 수이며, 전체 Qdrant 저장소의 모든 과거 컬렉션을 합한 수치는 아니다.

## 자동 검증

- `go mod tidy`, `go build ./...`, `go vet ./...`, `go test ./...` 통과.
- `golangci-lint run --no-config ./...` 통과, 0 issues. 도구 버전 2.15.0, Go 1.27.0으로 빌드된 바이너리 사용. 활성 검사는 errcheck·govet·ineffassign·staticcheck·unused였다.
- 실제 서비스 통합 테스트 `TestLiveBackend` 통과. 최초 실행은 약 59.5초.
- FFmpeg가 만든 H.264/H.265의 B 프레임 포함 영상에서 IDR 두 개의 PTS와 0초·1초 타임스탬프 일치 확인.
- 파서 테스트에서 H.264 비IDR, H.265 CRA, 잘못된 NAL 길이, Annex B·AVCC/HVCC 구분 확인.
- ZIP 41단계, 형제의 동일 압축, 중첩 다운로드, 경로 탈출·해제량 제한 확인.
- Windows Junction으로 조상 순환 두 개를 종료하면서 형제 별칭의 이미지 두 위치 유지 확인.
- 임베딩 503 재시도 시 Bearer 헤더가 중복되지 않는지 확인.
- API Key 환경 변수 참조를 설정에서 변경하면 재색인 없이 다음 검색 요청이 새 인증 정보를 사용하는지 확인.
- 테스트용 외부 서비스로 색인 도중 소스 제거, Qdrant 삭제 장애, 불완전 스캔, 여러 소스의 프로필 전환 경계를 검증. 이 검사는 실제 Qdrant 장애 실험과 구분한다.

`go test -race ./...`는 현재 타깃 `windows/arm64`에서 지원되지 않아 실행하지 못했다. `govulncheck`는 설치되어 있지 않아 실행하지 않았다. 이 두 검사를 통과한 것으로 간주하지 않는다.

## 남은 제약

- 웹 UI, 전체 캐시 용량 관리와 비정상 종료 임시 파일 정리는 후속 작업이다. 현재 원본별 처리·압축 해제량·작업 수·시간 제한은 구현했다.
- RAR5·solid RAR는 선택한 읽기 라이브러리의 지원을 사용하지만 이번 사용자 미디어 통합 샘플로 검증한 형식은 RAR4 store다. 암호화·분할 압축과 압축 내부 링크는 명시적인 오류로 처리한다.
- 이미지 EXIF 방향 적용과 JPEG·PNG·GIF·WebP 외 이미지 디코더는 후속 작업이다. 일반 영상의 브라우저 재생 가능성은 코덱에 따라 다르고 자동 재인코딩하지 않는다.
- 단일 프로세스·로컬 단일 사용자 범위다. SQLite 카탈로그의 JSON 레코드를 읽어 필터링하는 방식과 검색 후보 10,000개 제한은 대규모 라이브러리에서 추가 최적화가 필요하다.
- 같은 모델 별칭의 가중치가 바뀌었는지는 서버의 별도 체크섬이 없으면 자동으로 보장하지 못한다. 사용자가 `model_revision`을 변경해 재색인한다.
